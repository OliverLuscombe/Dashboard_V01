# Uploaded Overview pixel grid

Overview loads the explicitly applied CSV source on initial page load, on navigation back to Overview, and with **Refresh source / Refresh map**. Applying a source in Data does not transform or validate its measurements. Map Explorer, Compare, and Model Insights retain their synthetic demos. Uploaded Overview uses only actual mapped dates, readings and labels. Its period selectors, pixel raster, summary cards and inspector share one selected period. Synthetic date/split/region controls and the demo model teaser are not shown. Loading and failures never substitute demo data.

## Coordinates and missing values

- The raster is exactly 316 columns by 332 rows. CSV `(1, 332)` is the top-left image pixel `(0, 0)`; CSV `(316, 1)` is the bottom-right image pixel `(315, 331)`.
- Explicit x/y cells must parse as finite integers within x=1–316 and y=1–332. Decimal integer notation such as `3.0` is accepted. Latitude and longitude are optional inspector metadata, never positioning substitutes.
- Row-order mode revalidates that every stored position 0–104,911 exists exactly once before rendering or inspection. Position `p` maps to x=`p % 316 + 1`, y=`332 - p // 316`. Metadata row count alone is not sufficient.
- Mapped dates must parse as finite integers: year 1–9999 and month 1–12. Either column can be omitted. Both mapped columns must be valid when both are supplied. Invalid dates are excluded and counted; they are not interpreted as undated rows. With neither mapped column, the view says **Undated snapshot**, and month stepping/playback are disabled.
- Available periods come from actual valid mapped dates, even when those rows have no valid measurement or coordinate. A newly selected source starts at its earliest available period. Changing year retains the month if available, otherwise selects the earliest month in that year. Missing mapped date options are hidden; unavailable periods are not invented.
- Rows are ordered by saved position and ID. Within each period, the first row with a valid coordinate owns that pixel even when its measurement is invalid. Later rows at the same coordinate in that period are duplicates and ignored. Different dated periods never compete for the same pixel. With only year or only month mapped, uniqueness uses that supported date component; dates not supplied cannot be recovered.
- Numeric measurements accept finite values, including zero. Empty, nonnumeric, NaN and infinite values are transparent. This is parsing, not scientific range or quality validation; the app does not enforce concentration percentages or temperature/wind validity.
- Mapped marginal-ice-zone and cluster columns are rendered as discrete CSV labels, not inferred ice zones or computed clusters. Labels are whitespace-trimmed but otherwise preserved, including distinct numeric spellings. Empty/NA/null/non-finite labels and labels longer than 120 characters are missing. More than 32 distinct valid categories produces a clear error instead of merging categories or sending an unbounded legend.

The viewer reports all examined saved rows, selected-period rows, excluded invalid dates, valid unique rendered pixels, invalid coordinates/malformed rows, duplicate coordinates and invalid readings. Selected-period rows equal valid pixels plus the three skipped-period-row counts. Other periods and invalid-date rows do not contribute to the rendered pixels. Transparent pixels equal 104,912 minus valid pixels; skipped rows and missing grid cells are different quantities.

## Summaries and monthly analysis

Cards use the same selected-period first-row-per-coordinate policy as the raster, independently of the selected display layer. They report arithmetic mean mapped concentration (finite 0–100%) and mean finite SST (°C according to mapping), concentration ≥15% **pixel count**, and distinct valid cluster/MIZ CSV labels. Each includes its own valid pixel sample size. Missing columns or valid readings explicitly say **Not available**; zero is a real reading, not a missing sentinel. Continuous rasters retain all finite raw readings, including out-of-range concentration values, but those values are excluded from percentage summaries. No unit conversion or scientific quality validation is inferred.

Monthly concentration aggregation uses one valid concentration reading per coordinate and supported period. With a mapped year, it includes only that chosen year; without year mapping, it uses the available mapped months. The chart renders only when mapped month and concentration columns yield at least two distinct observed months with valid concentration values. Otherwise the panel explains which mapping or observations are missing. Points and sample sizes show the actual monthly arithmetic means; lines connect observations, not interpolated data. No missing months are filled, and the selected month does not remove other observed months from this chosen-year chart.

There is no validated ocean mask, grid resolution or cell area. Pixel counts are **not Antarctic extent or million km²**. No 25 km assumption is applied. CSV categories are not computed MIZ areas or trained clusters.

Continuous colours use the observed minimum and maximum of rendered pixels, with a midpoint colour for constant values. Discrete colours and legend labels come from actual values. The neutral background is not a reading. No coastline, graticule, region pins, interpolation, distance scale or scientific projection is added.

## Loading, inspection, and refresh

No active source returns to the unchanged demo. Missing measurement mapping, no valid readings, loading, and database/renderer failures have distinct states; a failed source read never falls back silently to synthetic observations.

The inspector reads current saved data with the same selected-period, coordinate and first-row rules. It displays all mapped readings, identifies the selected measurement, and shows optional finite latitude/longitude within their metadata bounds. A missing coordinate says **No observation at that pixel**; a stored row with an invalid measurement says **no valid reading**. Refresh the raster after edits so its snapshot matches the current inspector. Replacing or deleting the active source requires refreshing Overview.

Big reads and Pillow rendering run off the event loop in background events. State locks are used only for state updates. Reads use a consistent snapshot and one streamed, ordered, bounded DB row scan to discover periods, aggregate observed months and collect the selected-period raster input. Only that period is retained transiently in the worker, and its raster and cards use identical pixel ownership. Raw CSV rows and full pixel arrays are never put in serialized Reflex state; only compact period options, counts, formatted cards, monthly means/sample sizes and PNG metadata cross the state boundary. Request identifiers prevent slower obsolete renders or inspections from overwriting newer selections.

Runtime PNGs are created using Reflex's served upload directory and displayed with its upload-URL helper, not the static assets directory. Each completed refresh uses a new filename and removes the previous generated files for that session; stale render outputs and partial write failures are cleaned up. The database remains the source of record and no schema changes are made.

## Regression coverage

`scripts/test_overview_grid.py` covers coordinate corners, full row-order rasterization, finite numeric parsing, bounds, duplicates, transparent missing cells, constant and extreme numeric ranges, categorical legends and category limits, intact-position validation, source loading, compact PNG output, actual pixel lookup, database failures and file-write cleanup. It uses pure raster inputs and mocked reads, not a fabricated saved dataset. `scripts/test_overview_periods.py` adds in-memory date discovery, year-only/month-only/undated cases, missing columns, invalid readings/dates, selected-period raster and card switching, monthly aggregation/sample sizes, full-grid corners, inspector filtering and stale-result guards. Existing CSV/mapping coverage remains in `scripts/test_csv_validation.py`.
