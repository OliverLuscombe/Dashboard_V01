CSV READER, DATABASE, AND EXAMPLE DATA
=======================================

CSV reader
----------

The upload interface is in app/components/uploaded_data.py. It accepts one
UTF-8 CSV (including UTF-8 with BOM), up to 5 MB. The upload event and parser
are in app/states/uploaded_data.py:

* UploadedData.import_csv reads the selected file and calls _parse_csv.
* _parse_csv uses Python's csv.reader with strict quote handling. It checks
  the extension, encoding, nonempty unique headers, row and column limits,
  cell lengths, and that each data row has the same number of fields as the
  header. Quoted commas and newlines are parsed as CSV, not split naively.
* Ordinary CSVs keep their headers and values as strings. Values such as dates,
  formulas, leading zeroes and blank cells are not converted.
* Spatial CSVs are recognized when the first two header cells are Latitude
  and Longitude (case-insensitive and ignoring surrounding whitespace). The
  third and later headers are the measurement/value variables, for example:

      Latitude,Longitude,Wind speed,Surface temperature,Heat flux
      -75.5,123.25,12.4,-1.8,44.2

  Spatial files must have at least one measurement column. Each data row must
  have numeric decimal-degree coordinates in the ranges Latitude -90..90 and
  Longitude -180..180. The original header spelling and coordinate strings are
  retained in the imported record. This format is accepted for shared storage
  and preview/edit; it does not currently feed the scientific maps or charts.
* CSV validation tests are in scripts/test_csv_validation.py.

Database implementation
-----------------------

The SQLAlchemy models are in app/models.py; the schema migration is
db_migrations/versions/74d17ca12f33_add_uploaded_datasets_and_rows.py.

* uploaded_dataset stores dataset metadata: display name, original filename,
  ordered column names as JSON, row count, creation time, source and status.
* uploaded_dataset_row stores each record's ordered cell values as a JSON
  array, its position, and a foreign key to the dataset. A uniqueness
  constraint prevents duplicate row positions within a dataset; deleting a
  dataset cascades to its rows.
* Reflex supplies SQLAlchemy sessions through rx.session(). Import creates
  the metadata row, flushes to obtain its ID, adds all ordered row records, and
  commits them together using session.begin(). Thus a failed import is not a
  partially saved dataset.
* UploadedData._reload queries the shared catalogue and fetches just the
  selected 25-row page. Row edits/additions/deletions and dataset rename/delete
  also use transactions. Row and dataset locks plus comparison with the
  previously loaded values detect conflicting concurrent edits.
* Uploaded CSVs and edits are shared database records; the app does not keep
  the original uploaded file. This prototype has no authentication or private
  permissions, so do not upload confidential or personal data.

Antarctic polar view and sample data
------------------------------------

The Antarctic polar view implementation is in app/states/explorer.py:
Explorer.map_svg generates the illustrative south-polar SVG, graticules and
synthetic layer shapes. app/components/workspace.py:map_panel displays that SVG
inside the Map Explorer and overview interfaces.

The datasets shown as examples on the Data page are synthetic fixture cards
declared in app/components/workspace.py:data_page. Their demonstration values
and graphics are generated in app/states/explorer.py, including Explorer.trend,
Explorer._points, and Explorer.map_svg. They are not downloadable CSV files,
research observations, or rows in the upload database. The project contains
no standalone example .csv files. A small inline CSV example for parser tests
is in scripts/test_csv_validation.py.

The upload workspace does not connect imported rows to the map, charts,
comparison, or model calculations; those remain synthetic UI demonstrations.
